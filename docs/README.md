# QuackCit documentation

A [Citadel](https://www.citadel.org/) groupware/BBS server that runs *inside*
DuckDB. Start at [the README](../README.md) for what it is and why; these pages
are the detail.

## Using it

- **[Installing and building](install.md)** — build from source, install a
  release, and a first session driven by hand.
- **[Running a server](running.md)** — `deploy/quackcit.sh`, the admin CLI, the
  control channel, logging, and what a real install needs.
- **[TLS, authentication and certificates](tls.md)** — what is encrypted, how
  certificates are supplied, and the built-in ACME client that obtains and
  renews them.

## What it speaks

- **[Protocol coverage](protocols.md)** — one table per protocol: ports, RFCs,
  what is implemented, and what is not.
- **[The BBS](bbs.md)** — the native Citadel protocol, the server-side text
  client a plain `telnet` reaches, NNTP and XMPP.
- **[The web interface](web.md)** — webmail, the BBS in a browser, the
  groupware room views, CalDAV/CardDAV/JMAP, and the security posture.
- **[Mail](mail.md)** — SPF, DKIM, DMARC and DNSBL on the way in; signing,
  queueing and rate limits on the way out; Sieve filtering; the IMAP/POP3
  gateways over the room store.
- **[Mailing lists and feeds](lists.md)** — fanning a room out to subscribers,
  and pulling remote mailboxes and RSS/Atom into one.

## Working on it

- **[Architecture](architecture.md)** — the extension model, the tables, and
  why cross-extension state is SQL rather than C++.
- **[Contributing](contributing.md)** — layout, building, adding a listener, a
  module or a worker, the parity oracle, and the test suites.
- **[`TODO.md`](../TODO.md)** — the live backlog. It is the authoritative list
  of what is next; these pages describe what exists.
- **[`MEMORY.md`](../MEMORY.md)** — project history and the reasoning behind
  decisions that are not obvious from the code.
